The cell, the shape, the block

One mechanism, no script. The page sizes a cell; the engine names its shape; a block inside arranges itself by that name. Resize things on this page and watch the words change.

The cell is a size container named shape. Its size comes from the page — here a resizable box; on a real page a grid track. A cell must be definitely sized: a flex-grown cell reads as zero height.

/* mike.css, core.shape — nine rules, ONE definition */
:where(.cell) { container-name: shape; container-type: size; }
@container shape (width < 3lh) and (height < 3lh)
  { :where(.cell) > :where(*) { --shape: spot; --size: small; … } }
@container shape (aspect-ratio >= 15/8) and (3lh <= height < 8lh)
  { :where(.cell) > :where(*) { --shape: strip; --size: small; … } }
… seven more …

The block is the cell's child, so it CARRIES --shape and
--size, and every part inside inherits them.

2 · A part arranges by the word — flat

The figure's size steps per shape. Five cases, five lines, each readable on its own. Before, this was one nested var() five levels deep, and one wrong paren dropped the whole declaration with no error.

Why a style query and not a size query here: a size query would have to restate "width < 3lh and height < 3lh" — a second definition of spot. The word is read by name, so the definition stays in the engine. 
& > :where(strong) {
  --type: 3;
  @container style(--size: small)  { --type: 2; }
  @container style(--shape: strip) { --type: 1; }
  @container style(--shape: line)  { --type: 0; }
  @container style(--shape: rail)  { --type: 0; }
  @container style(--shape: spot)  { --type: -2; }
}

A style query reads the nearest ANCESTOR, never the element
itself — so a part can ask its block, but the block's own box
cannot ask itself. The box keeps the two-way toggles:

flex-direction: var(--is-rail, row)
                var(--no-rail, var(--is-run, row) var(--no-run, column));
writing-mode:   var(--is-rail, vertical-rl) var(--no-rail, horizontal-tb);

Two levels at most (the test refuses a third). More moves to a part.

3 · Showing and hiding is the gate layer's

A part lists the shapes it belongs in. The engine's last layer hides every gated part and shows it back only inside a matching cell. A block never writes display: none.

The readout row at the top of every demo block is nine words, each wearing one gate class — so the gates show you exactly one. That IS the mechanism, demonstrating itself. 
<b class="spot">spot</b><b class="line">line</b> … nine words, one shows
<small class="line rail slip sheet tile panel strip banner">net revenue</small>
<p class="sheet panel banner">only where there is room</p>

/* mike.css, visibility (the last layer) */
:where(.spot, .line, …, .banner) { display: none; }
@container shape (width < 3lh) and (height < 3lh)
  { :where(.spot) { display: revert-layer; } }

The inner block reads its own cell, never the outer one.
The outer cell holds <blk-nest>, a grid of two tracks that are themselves cells. Each inner block reads the shape of ITS cell: the narrow track is a rail or a spot while the wide one is a strip or a line. Nesting is just cells in a block in a cell — the same rule at every level. 
<div class="cell">              ← the page's
  <blk-nest>                    ← a block: a grid of…
    <div class="cell">…</div>   ← …cells (its tracks)
    <div class="cell">…</div>
  </blk-nest>
</div>

:where(blk-nest) {
  display: grid; grid-template-columns: 2.6lh minmax(0, 1fr);
  inline-size: 100%; block-size: 100%;
}

The engine re-sets --shape on EVERY cell's child, so the
inner block's word wins over the outer one for everything
inside it (custom properties inherit, nearest wins).

The rules, in one breath

  1. The cell is the page's: a grid track or a knob-sized box, definitely sized. Never flex-grown.
  2. The engine names the shape — nine rules in core.shape set --shape and --size on the cell's child. Defined once.
  3. A part arranges by @container style(--shape: …), flat, one line a case.
  4. The block's own box uses the toggles var(--is-X, a) var(--no-X, b), nested two levels at most; more moves to a part. A rail writes upright, so its "row" runs down the cell.
  5. Hiding is the gate classes' — a part lists where it belongs. A block never writes display: none, and never a size container query.
