```
   ┌─────────────────────────────────────────────────────────────┐
   │                  EVERY ELEMENT HAS TWO KNOBS                │
   │                                                             │
   │   --bg : -1  ←──── 0 ────→ +1     PAINT THE BACKGROUND      │
   │           (none)  (muted) (loud)                            │
   │                                                             │
   │   --fg : -1  ←──── 0 ────→ +1     PAINT THE INK             │
   │       (contrast) (none)  (chromatic)                        │
   │                                                             │
   │  Both axes are continuous. Both work in HTML and SVG.       │
   └─────────────────────────────────────────────────────────────┘


╔═══════════════════════════════════════════════════════════════════╗
║   THE TWO ROLES — MUTUALLY EXCLUSIVE                              ║
╚═══════════════════════════════════════════════════════════════════╝

   ┌──────────────────────────────┐    ┌──────────────────────────────┐
   │       .surface               │    │     CHROMATIC ACCENT         │
   │  (structural container)      │    │  (semantic colored element)  │
   ├──────────────────────────────┤    ├──────────────────────────────┤
   │                              │    │                              │
   │  Default --bg: -1            │    │  Set --bg: 0 … 1             │
   │     transparent, tracks      │    │     explicit chromatic       │
   │     parent                   │    │     paint                    │
   │                              │    │                              │
   │  Auto-depth via :has()       │    │  Theme-AWARE                 │
   │     more nesting = brighter  │    │     same --bg value renders  │
   │     surface (focus moves     │    │     theme-correct paint —    │
   │     toward the most-nested   │    │     muted endpoint sits      │
   │     content)                 │    │     near the active surface, │
   │                              │    │     loud endpoint shifts     │
   │  Theme-FLIPS                 │    │     between chromatic vivid  │
   │     light surfaces in light  │    │     (light) and P3 (dark)    │
   │     mode, dark surfaces in   │    │                              │
   │     dark mode                │    │  No structural role          │
   │                              │    │     no auto-depth            │
   │  Use for: cards, panels,     │    │                              │
   │     modals, sections, the    │    │  Use for: chips, badges,     │
   │     page itself, anything    │    │     status cards, brand      │
   │     holding content          │    │     callouts, swatches,      │
   │                              │    │     buttons, avatars         │
   │  Examples:                   │    │                              │
   │     <div class="surface">    │    │  Examples:                   │
   │       <h2>Title</h2>         │    │     <div                     │
   │       <p>Body…</p>           │    │       style="--bg: 0.55      │
   │     </div>                   │    │             --hue-lock: 145" │
   │                              │    │     >LIVE</div>              │
   │                              │    │                              │
   │                              │    │     <button                  │
   │                              │    │       style="--bg: 0.5">     │
   │                              │    │       Continue               │
   │                              │    │     </button>                │
   └──────────────────────────────┘    └──────────────────────────────┘

       Pick ONE per element. Never both. If you feel like you want
       both, you actually want a .surface CONTAINING a chromatic
       child element.

       Content always lives on .surface. Color is reserved for
       signals — buttons, badges, status, brand callouts. If your
       calendar event is a colored block, you're announcing it as
       a notification. If it's a surface, it's content.


╔═══════════════════════════════════════════════════════════════════╗
║   THE THREE HUE TOKENS                                            ║
╚═══════════════════════════════════════════════════════════════════╝

      --hue           page-level default. Cascades freely.
                      Set on :root or any subtree as a default
                      for everything below.

      --hue-shift     relative offset. Adds to the inherited
                      --hue. Stacks with parent shifts.
                      Use for: subtle subtree variation, families
                      of related-but-distinct cards.

      --hue-lock      absolute pin. Wins over --hue and
                      --hue-shift from above.
                      Use for: semantic colors (success/info/
                      warning/danger), brand-color elements,
                      anything that must be a specific hue
                      regardless of cascade.

   ┌─────────────────────────────────────────────────────────┐
   │  Resolution:                                            │
   │                                                         │
   │    --_h: var(--hue-lock,                                │
   │            calc(var(--hue) + var(--hue-shift)))         │
   │                                                         │
   │  If --hue-lock is set anywhere up the cascade,          │
   │  it wins. Otherwise: page hue + shifts.                 │
   └─────────────────────────────────────────────────────────┘

       Setting --hue-shift on a card and letting it cascade is
       the idiomatic way to make a row of related-but-distinct
       elements (KPI cards, category tiles, color-coded series
       in charts). Shift on the parent, inherit on the children,
       and any chromatic descendant — including SVG paths —
       picks up the rotated hue automatically.


╔═══════════════════════════════════════════════════════════════════╗
║   WHAT CHANGES WITH THEME (light ↔ dark)                          ║
╚═══════════════════════════════════════════════════════════════════╝

   .surface          ───►  FLIPS         (canvas inverts: light
                                          surfaces in light mode,
                                          dark surfaces in dark)

   --bg: 0…1         ───►  THEME-AWARE   (a 0.4 green renders as
                                          chromatic-vivid green in
                                          light mode, P3 green in
                                          dark mode — same --bg
                                          value, theme-correct paint)

   --fg: -1…0        ───►  FLIPS         (contrast pole derives
                                          from the surface, so
                                          ink lands correctly
                                          against either pole)

   --fg: 0…1         ───►  THEME-AWARE   (chromatic ink, mirrors
                                          the --bg behavior at
                                          the same value)

   --hue / --hue-lock /
   --hue-shift       ───►  STABLE        (hue is theme-orthogonal —
                                          a hue value of 145 stays
                                          145 in both themes)

   --border          ───►  FLIPS
   --Border          ───►  FLIPS

       Theme-aware ≠ theme-changing. The DESIGNER never writes
       theme-specific values — the same --bg: 0.55 produces a
       light-appropriate paint in light mode and a dark-appropriate
       paint in dark mode. Both are "the brand at this intensity"
       — the formula picks the right one for the active theme.


╔═══════════════════════════════════════════════════════════════════╗
║   THE FG AXIS — TWO MODES IN ONE NUMBER                           ║
╚═══════════════════════════════════════════════════════════════════╝

       --fg : -1 ────────── 0 ────────── +1
              │             │             │
              │             │             │
       max contrast    invisible      max chromatic
       (theme-aware)   (= surface)    (theme-aware)
              │                           │
              │                           │
       contextual ink                 brand ink
       (titles, body                  (highlights,
        text, default)                 chart lines,
                                       deliberate
                                       color)

       Negative half = contrast against the surface.
       Positive half = same color the surface would be at --bg = X.

       This means:  --fg: 0.4 produces the same color as --bg: 0.4
                    on a surface at the same hue.

       Combine with --hue-shift for chart series that participate
       in the cascade. Each series becomes "chromatic ink at hue
       offset N from the parent" — relative to the brand, not
       hardcoded.


╔═══════════════════════════════════════════════════════════════════╗
║   INTERACTION STATES                                              ║
╚═══════════════════════════════════════════════════════════════════╝

   Two markers, two intents:

      .clickable      Full interactive treatment.
                      Hover lifts (L + chroma), active presses
                      (L drops, contrast reduces). Cursor pointer.
                      Use for: anything you can click or tap.

      .hoverable      Soft response only.
                      Hover lifts (L + chroma). No active state,
                      no cursor change.
                      Use for: KPI cards, status displays, table
                      rows that highlight without navigating —
                      acknowledgment-only UI.

   ┌──────────────────────────────────────────────────────────────┐
   │  Buttons, links, [role="button"], and [tabindex] elements    │
   │  are .clickable by default. You don't add the class to them. │
   │                                                              │
   │  For non-semantic interactive elements (cards, list items,   │
   │  gallery tiles), add the marker explicitly.                  │
   └──────────────────────────────────────────────────────────────┘

   How it works:
   ────────────

      Hover  →  +L shift          (lift toward brighter)
                +chroma injection  (inject baseline tint —
                                    crucial: a near-neutral
                                    surface needs SOMETHING for
                                    the L shift to anchor against,
                                    so the hover always brings
                                    color even into pure neutrals)

      Active →  -L shift          (press toward darker)
                fg multiplier <1  (text contrast drops, reinforces
                                    the recessive/pressed feel)

   Both apply through the same formula that paints rest state.
   No hardcoded hover colors. No light/dark pairs. The interaction
   is a token-level perturbation; everything downstream re-resolves
   coherently — including borders, text contrast, chromatic ramp
   position, perception toggle, theme awareness.

       Don't write per-component :hover rules with hardcoded colors.
       That bypasses the system. Use the markers; tune the magnitudes
       at the config layer (see below) if needed.


╔═══════════════════════════════════════════════════════════════════╗
║   THE ONE FORMULA                                                 ║
╚═══════════════════════════════════════════════════════════════════╝

   inputs ────────────────────► formula ──────────────► outputs
   ──────                       ───────                 ───────

   --bg              (canvas)        │                  --_bg
   --fg              (ink)           │                  color
   --hue                             │                  fill (svg)
   --hue-lock                        ├──── one math ──► stroke (svg)
   --hue-shift                       │     pass         --border
   --depth (auto)                    │                  --Border
   theme (--cfg-dark)                │
   interaction state                 │
     (--_interact-l/c/fg-mul)        │
   chromatic config                  │
     (--cfg-color-*)                 │
   surface config                    │
     (--cfg-surf-*)                  │


╔═══════════════════════════════════════════════════════════════════╗
║   THE CASCADE IN ACTION                                           ║
╚═══════════════════════════════════════════════════════════════════╝

   Change ONE input on a parent…
   ─────────────────────────────

      <body style="--hue: 145">         ← change this
        <main class="surface">          ← surface re-resolves
          <article class="surface">     ← deeper surface re-resolves
            <h2>Title</h2>              ← --fg: -1 (default ink)
                                          re-resolves contrast
            <span style="--bg: 0.55">   ← chromatic accent ignores
              new                         hue cascade IF it has
            </span>                       --hue-lock; otherwise
                                          tints with --hue
            <button style="--bg: 0.5">  ← chromatic, picks up --hue
              Go                          (and gets hover/active
            </button>                     for free — buttons are
                                          .clickable by default)
          </article>
        </main>
      </body>

   …and EVERYTHING below updates because every output is a
   function of the same inputs through the same formula.

   No coordination. No tokens to keep in sync. No light/dark
   pairs to maintain. No per-state hover colors.

   Surfaces declare the canvas.
   Chromatic --bg declares semantic color.
   --fg declares ink intent.
   The three hue tokens decide what hue to render in.
   Markers declare interaction intent.
   The formula does the rest.


╔═══════════════════════════════════════════════════════════════════╗
║   THE CONFIG LAYER — SET ONCE, TUNE PROJECT-WIDE                  ║
╚═══════════════════════════════════════════════════════════════════╝

   Config tokens live on :root (or any subtree for scoped overrides).
   Grouped by what kind of decision they encode.

   ─── Brand ────────────────────────────────────────────────────────

      --hue              0…360         your brand hue
      --fg               -1…1          default ink intent
                                         (-1 = max contrast text)

   ─── Color character ──────────────────────────────────────────────

      --cfg-color-muted-l-light       muted endpoint L (light theme)
      --cfg-color-muted-l-dark        muted endpoint L (dark theme)
      --cfg-color-muted-c             muted endpoint chroma (shared)
      --cfg-color-loud-l-light        loud endpoint L (light theme)
      --cfg-color-loud-c-light        loud endpoint chroma (light)
      --cfg-color-loud-l-dark         loud endpoint L (dark theme)
      --cfg-color-loud-c-dark         loud endpoint chroma (dark)
      --cfg-color-curve               ramp easing exponent
                                         (1 = linear, 2 = quadratic
                                          bias toward muted)
      --cfg-color-surf-chroma         hue carry on neutral surfaces
                                         (0 = pure gray, ~0.02 =
                                          subtle warm/cool tint)
      --cfg-fg-tint                   hue carry on contrast ink

   ─── Surface depth ────────────────────────────────────────────────

      --cfg-surf-top-l-light          top-of-stack L (light)
      --cfg-surf-top-l-dark           top-of-stack L (dark)
      --cfg-surf-step-light           L drop per nesting (light)
      --cfg-surf-step-dark            L drop per nesting (dark)
      --cfg-surf-curve-light          depth curve (light)
      --cfg-surf-curve-dark           depth curve (dark)
      --cfg-surf-mid-light            depth midpoint (light)
      --cfg-surf-mid-dark             depth midpoint (dark)
      --cfg-surf-rng-light            depth range (light)
      --cfg-surf-rng-dark             depth range (dark)

   ─── Contrast perception ──────────────────────────────────────────

      --cfg-contrast-perception       0 = WCAG-strict
                                       1 = chroma-aware flip
                                           (compensates for
                                            Helmholtz-Kohlrausch —
                                            saturated cells flip
                                            to pale ink earlier)
      --cfg-contrast-perception-base  base shift for chromatic cells
      --cfg-contrast-perception-bias  per-chroma scaling factor

   ─── Interaction tuning ───────────────────────────────────────────

      --cfg-hover-l-shift             L lift on hover (% points)
      --cfg-hover-c-shift             chroma injection on hover
      --cfg-active-l-shift            L drop on active (% points)
      --cfg-active-fg-mul             contrast multiplier on active
                                         (<1 = lower contrast)

   ─── Theme switch ─────────────────────────────────────────────────

      Set on <html> via [data-ui-theme]:

         [data-ui-theme="light"] { --cfg-dark: 0 }
         [data-ui-theme="dark"]  { --cfg-dark: 1 }

      Every theme-split token lerps between -light and -dark
      counterparts based on this flag. Set the attribute, the
      whole system re-resolves.


╔═══════════════════════════════════════════════════════════════════╗
║   THE PUBLIC API, IN ONE BLOCK                                    ║
╚═══════════════════════════════════════════════════════════════════╝

   Per-element:
   ──────────
      --bg          -1 … 1     surface intensity (HTML elements)
      --fg          -1 … 1     ink intensity
      --hue         0 … 360    page-level hue (cascades)
      --hue-shift   any        relative offset (cascades)
      --hue-lock    0 … 360    absolute pin (cascades, overrides)

   Markers:
   ───────
      .surface                 structural container, depth cascade
      .clickable               click target, hover + active state
      .hoverable               soft hover acknowledgment, no active

   Project config (set once, on :root):
   ──────────────────────────────────
      Brand:                   --hue, --fg
      Color character:         11 tokens (muted, loud, curve, tints)
      Surface depth:           10 tokens (top, step, curve, mid, rng)
      Contrast perception:     3 tokens (mode + tunings)
      Interaction tuning:      4 tokens (hover/active magnitudes)
      Theme switch:            data-ui-theme attribute on <html>

   That's it.

   Five tokens per element say what color and ink it wants.
   Three markers say what role and interaction it has.
   The config layer is set once and tunes the whole system.
   Themes flip via one attribute.

   Surfaces hold content. Chromatic accents signal action or status.
   Markers declare interactivity. The cascade does the rest.
```
